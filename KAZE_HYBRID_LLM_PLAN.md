# Как перейти от rule based Kaze к AI-ассистенту с LLM

Короткий ответ: лучше делать гибрид, а не заменять правила целиком. Rule based слой должен оставаться "инструментами" приложения, а LLM будет понимать свободный текст, выбирать нужный инструмент и формулировать живой ответ.

## Рекомендуемая архитектура

1. Мобильное приложение хранит профиль, питание, тренировки, забеги и настройки.
2. Firestore синхронизирует данные пользователя.
3. Отдельный backend endpoint принимает запрос к Kaze.
4. Backend достает разрешенный контекст пользователя из Firestore.
5. LLM получает компактный контекст и список доступных действий.
6. Если нужен расчет, план или запись данных, backend вызывает локальную rule based функцию.
7. LLM превращает результат функции в нормальный человеческий ответ.

Такой подход лучше, чем "просто отправлять весь чат в модель", потому что расчеты калорий, БЖУ, планов тренировок и сохранение данных остаются контролируемыми.

## Что оставить rule based

- расчет нормы калорий и БЖУ;
- расчет дефицита/профицита;
- подбор тренировочного объема под цель, вес, возраст и частоту тренировок;
- сохранение блюд, тренировок, забегов и достижений;
- проверки безопасности: травмы, боль, медицинские ограничения;
- лимиты воды, калорий и реалистичных значений.

## Что отдавать LLM

- понимание свободной формулировки пользователя;
- уточняющие вопросы;
- разнообразие фраз;
- объяснение техники упражнений простым языком;
- составление рациона в более естественном формате;
- мягкий тон, мотивация, адаптация ответа под настроение.

## Почему не маленькая локальная LLM в приложении

Локальную маленькую модель можно добавить, но для мобильного приложения это обычно сложнее:

- модель занимает десятки или сотни мегабайт;
- нужны отдельные сборки и оптимизация под Android/iOS;
- ответы будут слабее, чем у облачной модели;
- батарея и нагрев устройства станут заметнее;
- сложнее обновлять поведение ассистента.

Практичный вариант для Kaze: backend + облачная LLM + строгие rule based инструменты. Локальную модель можно оставить как экспериментальный fallback для коротких фраз, но не как основной мозг.

## Минимальный следующий шаг

Сделать backend функцию `POST /assistant/reply`:

```json
{
  "uid": "firebase-user-id",
  "message": "Составь рацион на 2200 ккал",
  "conversationId": "chat-id"
}
```

Ответ:

```json
{
  "text": "Вот рацион на день...",
  "state": "food",
  "actions": []
}
```

Поле `state` уже можно связать с картинками Kaze: `food`, `workout`, `run`, `thinking`, `sleep`, `reminder`.
