# Как сейчас работает rule based модель Kaze

Сейчас Kaze не является LLM/нейросетевой моделью. Это локальный rule based ассистент: он получает текст пользователя, ищет в нем ключевые слова и выбирает один из заранее написанных сценариев ответа.

## Где находится логика

- Основной код: `lib/main.dart`
- Движок ответов: `_AssistantEngine`
- Точка входа: `_AssistantEngine.reply(String prompt)`
- Экран чата: `AssistantChatScreen`
- История: `AssistantConversation` и `AssistantMessage` внутри `AppData`

## Поток работы

1. Пользователь пишет сообщение в чате Kaze.
2. `AssistantChatScreen` создает `_AssistantEngine(data)`, где `data` - текущее состояние приложения.
3. Метод `reply(prompt)` переводит запрос в нижний регистр.
4. Дальше идут проверки ключевых слов через `_containsAny`.
5. Если найдено совпадение, вызывается нужный метод: рацион, список покупок, тренировка, техника упражнения и т.д.
6. Ответ добавляется в текущий чат и сохраняется вместе с остальными данными приложения.

## Какой контекст видит Kaze

Kaze получает объект `AppData`, поэтому может использовать:

- профиль пользователя: вес, рост, возраст, пол, цель;
- дневные цели по калориям и БЖУ через `_nutritionTargetsFor(data.profile)`;
- записи питания за последние 7 дней;
- завершенные тренировки за последние 7 дней;
- пробежки за последние 7 дней;
- историю чатов ассистента.

Краткий контекст собирается в `_contextSummary()`. Он добавляет в ответ вес, рост, возраст, цель, норму калорий/БЖУ и активность за последние 7 дней.

## Текущие сценарии

| Запрос пользователя содержит | Что делает Kaze | Метод |
| --- | --- | --- |
| `покуп`, `shopping` | Создает список покупок на неделю | `_shoppingList()` |
| `рацион`, `меню`, `план питания` | Генерирует рацион на день | `_mealPlan()` |
| `альтернатив`, `замен` | Предлагает здоровую замену блюда | `_healthyAlternative()` |
| `устал`, `тренировк`, `нагрузк` | Подбирает тренировку по усталости 1-10 | `_workoutByFatigue()` |
| `техника`, `выполнять`, `упражнен` | Объясняет технику упражнения | `_exerciseTechnique()` |
| `травм`, `боль`, `огранич` | Адаптирует нагрузку под ограничение | `_injuryAdaptation()` |
| `дефицит`, `профицит`, `калори` | Объясняет дефицит/профицит калорий | `_calorieBalance()` |
| `креатин`, `протеин`, `добавк`, `омега` | Дает базовые советы по добавкам | `_supplements()` |

Если ни одно правило не подошло, Kaze возвращает общий ответ со списком того, чем он может помочь.

## Плюсы текущего подхода

- Работает полностью локально.
- Не требует интернета и API-ключей.
- Ответы предсказуемые.
- Низкий риск случайно сгенерировать опасный или странный совет.
- Легко тестировать: один запрос всегда дает примерно один и тот же результат.

## Ограничения

- Нет настоящего понимания смысла запроса.
- Если пользователь сформулировал мысль иначе, правило может не сработать.
- Ответы заранее заготовлены и быстро начинают повторяться.
- Нельзя гибко вести диалог, уточнять детали и помнить сложный контекст.
- Нельзя качественно разбирать состав блюда, медицинские ограничения или нестандартные цели.

## Как расширять

Чтобы добавить новый сценарий:

1. Добавить проверку ключевых слов в `_AssistantEngine.reply`.
2. Создать отдельный метод ответа, например `_waterIntakeAdvice()`.
3. Использовать `AppData`, если ответ должен учитывать профиль, питание, тренировки или пробежки.
4. Добавить тесты на несколько типичных формулировок запроса.

Пример направления для следующего расширения: отдельные правила для воды, сна, восстановления, плато веса и анализа конкретного блюда.
